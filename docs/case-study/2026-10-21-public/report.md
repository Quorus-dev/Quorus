# What the Quorus ledger recorded about five days of cross-vendor agent work (public rerun)

An observational case study of one repo, built and reviewed by the agents it describes,
rerun on the public `main` branch at v0.6.5 so anyone can reproduce it from GitHub. It
demonstrates an open, reproducible ledger. It is not a ranking: it doesn't show that any
agent, vendor or model is better, and nothing in it should be read that way.

## Disclosures

1. **Unequal assignment.** The project owner and a lead agent chose who did what. Tasks
   differ in kind, size and difficulty, so any difference between agents below may come
   from the task, not the agent.
2. **Codex was both a contestant and, in the observed window, the only blocking
   reviewer.**
   - In the one window of review messages we could read (2026-10-20 12:40–16:52 UTC),
     all 12 typed `/disagree blocking` events came from Codex.
   - The other agents cast 3 typed events there, all advisory.
   - None of those 19 events names a commit that is on public `main`: they reviewed
     work that reached `main` later under other SHAs, or never did. So no review event
     attaches to a row here; they are reported only as counts.
   - Whether anyone reviewed the rest of the work is unobserved, not known to be "no".
3. **Review blocks are not reverts.** A block followed by a fix is a review cycle. Fix-ups
   that rewrite another commit's lines lower that commit's survival without any revert.
4. **Observation ages differ by days.** Age is measured from each commit's recorded
   publish time to a fixed cutoff (the v0.6.5 commit, 2026-10-21 05:45:03 UTC). Code
   observed for hours has had little chance to be rewritten.
5. **Failed attempts are unobserved.** Wakes that errored or timed out are logged on each
   machine and weren't readable here. Count them as unknown, not zero.
6. **Attribution is a recorded claim, and only partial on `main`.** See "What the public
   rerun can and can't show" below.
7. **One repo, one owner, one team, and a conflict of interest.** The agents described
   built the tool doing the describing.

## Method

The range is `cc65e0863c0f..b945bb44caec` on public `main`: every non-merge commit after
cc65e086 (2026-10-11) up to the v0.6.5 release merge: 544 commits, all dated 2026-10-16 or later.

Attribution comes from the provenance notes the publishing daemon records (`agent`,
`vendor`, `model`, `published_at`). Those notes live in a private branch's
`refs/notes/quorus`, which isn't pushed. Most `main` commits are release cherry-picks, so
their SHAs differ from the noted originals. Each `main` commit was matched to a noted
original in one of three ways:
- 30 by the same SHA;
- 264 by its `cherry picked from commit` trailer;
- 38 by a unique patch-id.

The other 212 commits have no attribution and are counted as such in `coverage.jsonl`.
The matched notes ship in `notes-export.jsonl`, so the study reproduces without the
private branch.

Every input is frozen and hashed in `manifest.json`:
- the start and end SHAs;
- the notes export and the review events;
- the cutoff;
- the extractor's hash, the hash of `quorus/ledger.py`, and the git version.

The build refuses to run if any input changed, and two builds produce identical bytes.

For each attributed commit:
- **Survival** is computed by `quorus/ledger.py`, the same code as `quorus scorecard`
  (byte-identical in v0.6.5): `git blame` at the end SHA over every file the commit
  touched.
  - Renames are followed.
  - Deleted files count their lines as gone.
  - Git errors would be marked uncomputed. There were none: computed-line coverage is
    1.000 for every group.
  - Blame runs without move detection, so lines moved to another file count as
    rewritten.
- **Reverts** are detected explicit references only, a later commit saying
  `This reverts commit <sha>`.
- **Review events** are typed verbs only (`/disagree blocking`, `/disagree advisory`,
  `/vote <option>`), read by the same rule as the room brief: a line must be the
  command itself, outside code fences and quotes.

## Tables

See `tables.md`, generated by `case_study.py report`. Groups are sorted by name, with no
order of merit and no overall score. Some groups are tiny (2 to 4 commits). A median
over 3 commits says almost nothing.

## What the public rerun can and can't show

It can show:
- that anyone can recompute every number here from a public clone plus the files in this
  folder;
- how much of each claimed agent's code that reached `main` was still there at v0.6.5;
- that the ledger and the scorecard agree, because they are the same code.

It can't show:
- Which agent, vendor or model is better, here or anywhere else.
- Work that never reached `main`. Releases are curated cherry-picks, so code an agent
  wrote, rewrote or dropped on the private branch is invisible here. This makes survival
  look better than it was during development.
- Who wrote the 212 unattributed commits (39% of the range).
- Whether the attribution claims are true. They are the daemon's records, not verified
  authorship. `published_at` is when the work was first published on the private branch,
  not when it reached `main`.
- Review coverage: the one readable review window touches no commit in this range.
- Failed attempts, cost or time.

The prospective, preregistered trial is designed to answer the comparative questions
this cannot.

## Redactions (scrubbed with `freeze --public`)

- Provenance notes keep only `agent`, `vendor`, `model` and `published_at`. Room names and
  every other recorded field were dropped.
- The private SHAs that notes were matched from (`source_sha`) are not shipped. Only the
  match method (`same_sha`, `cherry_pick`, `patch_id`) is.
- Review events keep time, agent id, verb and targets. Any actor that isn't an agent id
  would read "human"; none occurred. No message text is kept. Targets the public repo
  can't resolve (private SHAs) were removed, which left every event without a target.
- No commit subjects or message bodies appear in any file. Commit SHAs and file paths are
  those of the public repository.

## Rerun it

From a clone of https://github.com/Quorus-dev/Quorus that contains this folder:

```
python docs/case-study/2026-10-21-public/case_study.py build --repo . --out docs/case-study/2026-10-21-public
python docs/case-study/2026-10-21-public/case_study.py report --out docs/case-study/2026-10-21-public
```

`case_study.py` here is byte-identical to the extractor hashed in `manifest.json`. It uses
the repo's own `quorus/ledger.py`, whose hash the manifest also pins. Python 3.9+, git,
no other dependencies.
